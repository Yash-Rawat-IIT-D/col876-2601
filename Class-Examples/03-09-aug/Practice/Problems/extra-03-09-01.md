## Part A — Propositional logic, intuitionistically

Do all of these in tactic mode first. Then pick any three and rewrite them as
**proof terms** (`theorem foo : ... := fun p q h => ...`), with no `by`. That
exercise, more than any other, makes `intro`/`apply`/`exact` stop being magic
words: `intro` is `fun`, `apply` is application, and a proof is a program.

### Q1. The implication fragment [★]

**Prove**

```lean
theorem imp_id    : ∀ p : Prop, p → p
theorem imp_const : ∀ p q : Prop, p → q → p
theorem imp_swap  : ∀ p q r : Prop, (p → q → r) → (q → p → r)
theorem imp_comp  : ∀ p q r : Prop, (p → q) → (q → r) → (p → r)
```

**Think about:** these four are the axioms/combinators of the implicational
calculus. Write next to each the type of the corresponding program (`imp_comp` is
function composition; what is `imp_const`?).

### Q2. Conjunction [★]

**Prove**

```lean
theorem and_comm'  : ∀ p q : Prop, p ∧ q → q ∧ p
theorem and_assoc' : ∀ p q r : Prop, (p ∧ q) ∧ r → p ∧ (q ∧ r)
theorem curry      : ∀ p q r : Prop, (p ∧ q → r) → (p → q → r)
theorem uncurry    : ∀ p q r : Prop, (p → q → r) → (p ∧ q → r)
```

**Strategy:** to *use* a conjunction, `cases h with | intro hp hq => ..` (or
`obtain ⟨hp, hq⟩ := h`). To *build* one, `constructor` / `apply And.intro`, or the
anonymous constructor `⟨hp, hq⟩`. Use each style at least once.

### Q3. Disjunction [★]

**Prove**

```lean
theorem or_comm'   : ∀ p q : Prop, p ∨ q → q ∨ p
theorem or_assoc'  : ∀ p q r : Prop, (p ∨ q) ∨ r → p ∨ (q ∨ r)
theorem or_elim    : ∀ p q r : Prop, (p ∨ q) → (p → r) → (q → r) → r
theorem or_idem    : ∀ p : Prop, p ∨ p → p
```

**Note:** `or_elim` is the class's `del` theorem. Recall the warning from
`aug_10.lean` that the soundness of ∨-elimination is exactly what makes case
analysis legitimate.

### Q4. Distribution [★★]

**Prove** both directions of each:

```lean
theorem and_or_distrib : ∀ p q r : Prop, p ∧ (q ∨ r) ↔ (p ∧ q) ∨ (p ∧ r)
theorem or_and_distrib : ∀ p q r : Prop, p ∨ (q ∧ r) ↔ (p ∨ q) ∧ (p ∨ r)
```

**Strategy:** `constructor` splits the `↔` into `mp` and `mpr`. Both directions
are intuitionistically fine — no classical reasoning anywhere. Confirm that by
checking you never used `Classical.em`.

### Q5. Negation basics [★★]

**Prove**

```lean
theorem not_not_intro : ∀ p : Prop, p → ¬¬p
theorem not_contra    : ∀ p : Prop, ¬(p ∧ ¬p)
theorem contrapositive: ∀ p q : Prop, (p → q) → (¬q → ¬p)
theorem not_iff_self  : ∀ p : Prop, ¬(p ↔ ¬p)
```

**Strategy:** unfold what `¬p` *is* — `p → False`. Every one of these is then an
exercise in `intro` and `apply`, exactly like Q1. `contradiction` and
`exact absurd h1 h2` are shortcuts; do at least one of them the long way, ending
in `exact hnp hp`.

### Q6. Double negation gymnastics [★★★]

**Prove** (all four are intuitionistically valid, which is the surprise):

```lean
theorem not_not_not : ∀ p : Prop, ¬¬¬p → ¬p
theorem nn_em       : ∀ p : Prop, ¬¬(p ∨ ¬p)
theorem nnimp1      : ∀ p q : Prop, ¬¬(p → q) → ¬¬p → ¬¬q
theorem nnimp2      : ∀ p q : Prop, (¬¬p → ¬¬q) → ¬¬(p → q)
```

The last two are the class's `nnimp1`/`nnimp2`. Do them *without* looking at
`Basic-test.lean` or `induction.lean` first; then compare your proof with the
class's and note where they differ.

**Think about:** `nn_em` says the excluded middle is not *refutable*, even though
it is not provable. In one comment line, say what that gap means.

### Q7. What intuitionistic logic will not give you [★★]

For each, decide whether it is provable in Lean **without** classical axioms.
Prove the ones that are; for the others, prove the double-negated version instead
(`¬¬φ`), and then prove the original using `Classical.em` or `by_contra` and say
which one you needed:

```lean
1.  ∀ p : Prop, ¬¬p → p
2.  ∀ p q : Prop, (¬q → ¬p) → (p → q)
3.  ∀ p q : Prop, ((p → q) → p) → p            -- Peirce's law
4.  ∀ p q : Prop, ¬(p ∧ q) → ¬p ∨ ¬q
5.  ∀ p q : Prop, ¬p ∨ ¬q → ¬(p ∧ q)
6.  ∀ p q : Prop, ¬(p ∨ q) ↔ ¬p ∧ ¬q
```

**Deliverable:** a table in a comment, one row per item: provable / needs
classical / which tactic. This is the single most useful thing in this file.

### Q8. The class's exercises, restated [★★]

**Prove**

```lean
theorem fact1 : ∀ p q : Prop, p → ¬p → ¬¬q
theorem fact2 : ∀ p q : Prop, q → ¬p → ¬¬q
theorem exercise : ∀ α β μ : Prop, (¬(α → β) → ¬¬(α → μ)) → α → ¬β → ¬¬μ
```

**Think about:** `fact1` and `fact2` have the same statement shape but completely
different proofs — one goes through explosion, the other never touches `p`. Say
which is which in a comment.

### Q9. `↔` as a proposition [★★]

**Prove**

```lean
theorem iff_refl'  : ∀ p : Prop, p ↔ p
theorem iff_symm'  : ∀ p q : Prop, (p ↔ q) → (q ↔ p)
theorem iff_trans' : ∀ p q r : Prop, (p ↔ q) → (q ↔ r) → (p ↔ r)
theorem iff_and    : ∀ p q : Prop, (p ↔ q) → (p ∧ q) ∨ (¬p ∧ ¬q) ∨ True
```

**Strategy:** `cases h` on an `↔` hypothesis gives you the two implications;
`h.mp` and `h.mpr` project them directly. The fourth is deliberately trivial —
notice that a badly stated theorem can be true and useless. Restate it into
something with content.

## Part B — Quantifiers

Work with `α β : Nat → Prop` (or `ℕ → Prop` if you imported Mathlib).

### Q10. Introduction and elimination [★]

**Prove**

```lean
theorem all_inst  : ∀ (P : Nat → Prop), (∀ x, P x) → P 7
theorem ex_intro' : ∀ (P : Nat → Prop), P 7 → ∃ x, P x
theorem ex_elim'  : ∀ (P : Nat → Prop) (q : Prop), (∃ x, P x) → (∀ x, P x → q) → q
```

**Strategy:** `exists 7` (or `⟨7, h⟩`) to build; `obtain ⟨x, hx⟩ := h` to consume.
Note the asymmetry with `∀`: you *apply* a `∀`, you *destructure* an `∃`.

### Q11. Quantifiers commute with the connectives — sometimes [★★]

**Prove** the true ones, refute the false ones:

```lean
1.  (∀ x, P x ∧ Q x) ↔ (∀ x, P x) ∧ (∀ x, Q x)
2.  (∃ x, P x ∨ Q x) ↔ (∃ x, P x) ∨ (∃ x, Q x)
3.  (∀ x, P x) ∨ (∀ x, Q x) → (∀ x, P x ∨ Q x)
4.  (∀ x, P x ∨ Q x) → (∀ x, P x) ∨ (∀ x, Q x)
5.  (∃ x, P x ∧ Q x) → (∃ x, P x) ∧ (∃ x, Q x)
6.  (∃ x, P x) ∧ (∃ x, Q x) → (∃ x, P x ∧ Q x)
```

**Strategy for the false ones:** you cannot "refute" a `∀ P Q` statement without
instantiating. Pick concrete predicates on `Nat` (`fun n => n = 0` and
`fun n => n ≠ 0` will do a lot of work), state the negation as a theorem, and
prove it.

### Q12. Negation and quantifiers [★★]

**Prove** what is intuitionistically provable, and mark the rest:

```lean
1.  (¬∃ x, P x) ↔ (∀ x, ¬ P x)
2.  (∃ x, ¬ P x) → ¬(∀ x, P x)
3.  (¬∀ x, P x) → (∃ x, ¬ P x)
4.  (∃ x, P x) → ¬(∀ x, ¬ P x)
```

Item 4 is the class's `fact4`. Item 3 is the one that needs classical logic —
find where the proof breaks and say precisely which step you cannot take.

### Q13. `fact5`, with and without the crutch [★★★]

The class's version assumed double-negation elimination as a hypothesis:

```lean
theorem fact5 : ∀ (P : Nat → Prop) (q : Prop), (¬¬q → q) →
                  (¬∀ x, ¬ P x) → (∀ x, P x → q) → q
```

**Prove it.** Then **prove the intuitionistic version**, which needs no `DNE`
hypothesis because the conclusion is weakened:

```lean
theorem fact5' : ∀ (P : Nat → Prop) (q : Prop),
                   (¬∀ x, ¬ P x) → (∀ x, P x → q) → ¬¬q
```

**Think about:** compare the two proofs. The `DNE` hypothesis is doing exactly
one thing; point at the line.

### Q14. Nested quantifiers and order [★★]

**Prove** or refute:

```lean
1.  (∃ x, ∀ y, R x y) → (∀ y, ∃ x, R x y)
2.  (∀ y, ∃ x, R x y) → (∃ x, ∀ y, R x y)
3.  (∀ x, ∀ y, R x y) ↔ (∀ y, ∀ x, R x y)
```

with `R : Nat → Nat → Prop`. For item 2, `R := fun x y => x = y` is a
counterexample — turn that observation into an actual Lean proof of the negation.

**Think about:** item 1 vs item 2 is the difference between "there is one thing
that works for everybody" and "everybody has something that works". Most
specification bugs in real systems are exactly this swap.

**Prove**

theorem pred_mono : ∀ (P Q : Nat → Prop), (∀ x, P x → Q x) → (∃ x, P x) → (∃ x, Q x)

## Part C — Enumerated types and exhaustive case analysis

### Q17. `day`, revisited [★]

Reuse the class's `day` type and `nextDay`. **Prove**

```lean
theorem nd_thursday : nextDay .thursday = .friday
theorem nd_involutive_false : nextDay (nextDay .monday) ≠ .monday
theorem nd_never_fixed : ∀ d : day, nextDay d ≠ d
```

**Strategy:** the first two are `rfl` / `decide` / `simp [nextDay]`. The third
needs `cases d` — seven goals, each closed by the fact that distinct constructors
differ. Try `cases d <;> simp [nextDay]` and, if that leaves goals, find out what
`decide` needs (a `DecidableEq day` instance — add `deriving DecidableEq`).

### Q18. `nextWorkingDay` [★★]

Reuse your `nextWorkingDay`. **Prove**

```lean
theorem nwd_fri_sun  : nextWorkingDay .friday = nextWorkingDay .sunday
theorem nwd_never_weekend : ∀ d : day, nextWorkingDay d ≠ .saturday ∧ nextWorkingDay d ≠ .sunday
theorem nwd_idem_on_working : ∀ d : day, nextWorkingDay (nextWorkingDay d) = nextWorkingDay (nextDay (nextWorkingDay d))
```

**Careful:** the third may be false as stated. Check it on paper *first*, and if
it is false, find the counterexample and restate it into something true. Learning
to distrust a plausible statement is the point.

### Q19. A second enumerated type [★]

**Define** your own `Month` (twelve constructors) with

```lean
def daysIn : Month → Nat            -- ignore leap years
def isLong : Month → Bool           -- 31 days
```

**Prove**

```lean
theorem long_iff_31 : ∀ m : Month, isLong m = true ↔ daysIn m = 31
theorem daysIn_pos  : ∀ m : Month, daysIn m ≥ 28
```

**Strategy:** `cases m <;> simp [isLong, daysIn]` and, where that is not enough,
`decide`. Twelve cases is where `<;>` earns its keep.

### Q20. Case analysis is not induction [★★]

**Prove**

```lean
theorem day_finite : ∀ d : day, d = .monday ∨ d = .tuesday ∨ d = .wednesday ∨
                                 d = .thursday ∨ d = .friday ∨ d = .saturday ∨ d = .sunday
```

**Think about:** why does `day` get a `cases` principle but no useful `induction`
principle? Compare `#print day.rec` with `#print Nat.rec` and point at the
difference. That difference is precisely "no recursive constructor".

## Part D — Lists, length and append

### Q21. `myLength` and prepending [★]

Reuse `myLength` from `prac1.lean`. **Prove**

```lean
theorem len_prep_plus_one : ∀ (α : Type) (l : List α) (n : α), (n :: l).length = l.length + 1
theorem len_prep_longer   : ∀ (α : Type) (l1 l2 : List α) (n : α),
                              l2 = (n :: l1) → l2.length > 0 ∧ l2.length > l1.length
theorem myLength_eq       : ∀ (α : Type) (l : List α), myLength α l = l.length
```

**Strategy:** the second is the class's exercise — `apply And.intro` (or
`constructor`) to split the goal, then `simp [h]`. The third is your first real
induction on a list.

### Q22. Append [★★]

**Prove**

```lean
theorem append_len : ∀ (α : Type) (l1 l2 : List α), (l1 ++ l2).length = l1.length + l2.length
theorem append_len_greater : ∀ (α : Type) (l1 l2 : List α),
                               (l1 ++ l2).length ≥ l1.length ∧ (l1 ++ l2).length ≥ l2.length
theorem append_nil_right : ∀ (α : Type) (l : List α), l ++ [] = l
theorem append_assoc' : ∀ (α : Type) (l1 l2 l3 : List α), (l1 ++ l2) ++ l3 = l1 ++ (l2 ++ l3)
```

**Strategy:** `append_len` is the class's proof, ending in `ac_rfl` — do it that
way once, then again with `omega` instead, and note what `ac_rfl` is for.
`append_len_greater` is the exercise left open in `prac2.lean`; derive it from
`append_len` rather than by a fresh induction.

### Q23. Empty lists [★★]

**Prove**

```lean
theorem len_zero_iff_nil : ∀ (α : Type) (l : List α), l.length = 0 ↔ l = []
theorem append_eq_nil    : ∀ (α : Type) (l1 l2 : List α), l1 ++ l2 = [] → l1 = [] ∧ l2 = []
```

**Strategy:** both are `cases l` (not induction — nothing recurses). The `→`
direction of the first needs you to refute `(x :: t).length = 0`; which principle
is that?

### Q24. Reverse [★★]

Reuse `myRev` from `prac1.lean`. **Prove**

```lean
theorem myRev_len   : ∀ (l : List Nat), (myRev l).length = l.length
theorem myRev_eq_lib: ∀ (l : List Nat), myRev l = List.reverse l
theorem rev_idemp   : ∀ (l : List Nat), List.reverse (List.reverse l) = l
```

**Think about:** the class proved `rev_idemp` with a bare `simp` and wrote "woah
this worked??". Find out *why*: `simp` has `List.reverse_reverse` in its default
set. Now try proving `myRev_eq_lib` — for which `simp` has nothing — and feel the
difference between a lemma the library has already proved and one you must.

### Q25. Membership [★★]

**Prove**

```lean
theorem mem_append_left  : ∀ (l1 l2 : List Nat) (x : Nat), x ∈ l1 → x ∈ (l1 ++ l2)
theorem mem_cons_self    : ∀ (l : List Nat) (x : Nat), x ∈ (x :: l)
theorem contains_iff_mem : ∀ (l : List Nat) (x : Nat), l.contains x = true ↔ x ∈ l
```

**Strategy:** `#check List.contains` and `#check List.Mem` first. The third is a
`Bool` ↔ `Prop` bridge — the same shape as `ev_iff_evb` in the 10–16 material, and
the library may already have it (`List.contains_iff_mem` or similar). Find it
with `exact?` before proving it by hand, then prove it by hand anyway.

### Q26. `len_sup_long`, the statement that was wrong [★★★]

From `prac2.lean`: "given a list `l1`, any other list `l2` which contains all
elements of `l1` must have length at least that of `l1`."

1. **State** it in Lean, for `List Nat`, using `List.contains` or `∈`. Be careful
   with the quantifier order and the parentheses.
2. **Refute** it: prove the negation of your own statement, using the
   counterexample `l1 = [1,1,1,1]`, `l2 = [1,2]`.
3. **Repair** it by adding a distinctness hypothesis, and state the fixed
   version. You may leave the proof as `sorry` (it is Practice 05 Q12 in the
   10–16 set, where you have the machinery to attempt it).

**Think about:** you have now done the full cycle — state, disbelieve, refute,
repair. Write three lines on what the original English sentence left ambiguous
that the Lean statement forced you to pin down.

### Q27. Two lists, one theorem [★★]

**Prove**

```lean
theorem len_map_append : ∀ (l1 l2 : List Nat),
    (List.map (fun x => x + 1) (l1 ++ l2)).length = l1.length + l2.length
```

**Strategy:** three library facts compose here (`List.length_map`,

### Q28. Your own list type, one more time [★★]

Recall the class's `myList` declaration (which you defined but barely used
because Lean's `List` took over).

**Define** `myLength'` and `myApp` **for `myList`, not `List`**, and prove

```lean
theorem myApp_len : ∀ (α : Type) (l1 l2 : myList α),
    myLength' (myApp l1 l2) = myLength' l1 + myLength' l2
```

**Think about:** the proof is character-for-character the same as `append_len`,
except that no `simp` lemma fires automatically. That is the whole difference
between a library type and your own — and the reason the 10–16 set makes you
build `MyNat` by hand.
